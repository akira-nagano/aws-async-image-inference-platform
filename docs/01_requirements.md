# 要件定義

## 1. 機能要件

### 1.1 認証

- ユーザーはCognito User Poolで管理する。
- AWS環境のWeb UIは、有効なセッションがなければCognitoマネージドログインへ自動遷移し、Authorization Code GrantとPKCEで認証する。
- Web UIで保存した日本語または英語をCognitoの`lang`パラメータへ渡し、マネージドログイン、自己登録、パスワード再設定でも同じ言語を維持する。
- AWS環境の自己登録ではメールアドレスを必須入力とし、そのアドレスへ送信した確認コードで検証する。
- 自己登録を確認したユーザーは`tier-basic`へ自動所属する。
- AWS環境のWeb UIはユーザーのパスワードをアプリケーション内で取得しない。
- Flociローカル環境だけは、Cognito互換APIへユーザー名・パスワードを直接送る開発用画面を使用できる。
- Cognitoマネージドログアウトと、その後の自動ログイン再遷移ではアプリ内の認証カードを挟まず、全画面で遷移中であることを表示する。認証カードは遷移開始に失敗した場合の再試行にだけ使用する。
- API GatewayはCognitoが発行したJWTを検証する。
- 未認証リクエストは401を返す。

### 1.2 Tier

- TierはCognitoグループで管理する。
- TierグループはBasic、Standard、Premiumの3段階とする。
- ユーザーはTierグループのいずれか1つだけに所属する。
- Tier未所属または複数Tier所属は設定不備として403を返す。
- Tier上限値は環境設定で変更可能とする。

### 1.3 画像アップロード

- JPEG/PNGをWeb UIでファイル選択、ドラッグ&ドロップ、または対応端末のカメラ撮影から入力できる。
- ブラウザはS3署名付きURLで画像を直接アップロードする。
- API Gatewayへ画像バイナリを送らない。
- ファイルサイズとContent-TypeをUIとサーバー側の両方で検証する。
- 入力画像は一定日数後にLifecycleで削除する。

### 1.3.1 Web UI

- ページタイトルは「AI画像検索デモ」とする。
- 日本語と英語を即時に切り替えられ、選択言語を同じブラウザへ保存する。
- Apple風の半透明マテリアル、システムタイポグラフィ、余白、角丸、奥行き、抑制された動きを一貫して使用する。
- `prefers-reduced-motion`、`prefers-reduced-transparency`、`prefers-contrast`を尊重する。

### 1.4 Job受付

- Job作成APIは非同期で202を返す。
- `Idempotency-Key` を受け付ける。
- Tier上限到達時は429を返す。
- システム全体上限到達時は503を返す。
- Job ID、状態確認URL、現在枠、上限を返す。

### 1.5 推論

- Step Functions Standardが推論ワークフローを管理する。
- LambdaコンテナはS3から画像を読み込み、上位3候補を返す。
- 実モデル未提供期間はスタブモデルを利用する。
- Jobの成功、失敗、タイムアウトを保存する。

### 1.6 状態確認

- ユーザーは自分のJob状態だけ取得できる。
- UIは2〜5秒間隔でポーリングする。
- 完了時に推論候補、信頼度、処理時間、モデルバージョンを表示する。

### 1.7 枠解放

- 成功、失敗、タイムアウト、キャンセルで枠を解放する。
- 同じ完了処理を複数回実行しても二重解放しない。
- 期限切れJobはReaperが検出して枠を回収する。

## 2. 非機能要件

### 2.1 セキュリティ

- S3はすべて非公開。
- フロントエンドS3はCloudFront OAC経由のみ。
- APIはJWT認証を必須とする。
- IAMは最小権限。
- ログへJWT、画像内容、署名付きURLを出力しない。
- 保存データを暗号化する。

### 2.2 可用性

- マネージドサービスを優先する。
- Jobの実行状態をDynamoDBに永続化する。
- Step Functionsの失敗経路とReaperの両方で枠回収する。

### 2.3 性能

現時点で実モデルがないため、以下を計測項目とする。

- コンテナ非圧縮サイズ
- Lambda初期化時間
- モデルロード時間
- 最大RSS
- ウォーム推論時間
- Job受付レイテンシ
- 同時Job受付時のDynamoDB競合

### 2.4 運用

- CloudWatch Logs保持期間を設定する。
- Job失敗率、タイムアウト、429、503、Reaper回収数を監視する。
- Tier設定はコードレビュー可能な形で管理する。
- CDKで全リソースを再現できる。

### 2.5 ローカル開発

- Flociで主要なAWS依存をローカル再現する。
- DockerコンテナでLambdaイメージを実行する。
- CloudFront等のエッジ機能はAWS開発環境で補完試験する。
